# ex_24 -- Bayesian optimization benchmark (Figure 5; Supplementary Section S7, Figure S3, Tables S17 and S18)
# Paper: main-text Figure 5 (ClogP on AqSolDB and QED on ZINC250k: regret per round at 16 and 1024 dims, regret AUC vs
#   size; Morgan + Tanimoto vs HDF + linear kernel, random search dashed), Supplementary Section S7 (text numbers),
#   Supplementary Figure S3 (regret AUC of all nine objectives, four surrogates). Tables S17/S18 (objectives and
#   settings) are written by hand from the constants of bo_benchmark.py (OBJECTIVES, budgets, kernels), not generated.
#   Supplementary Figure S4 (wall-clock) comes from the original benchmark ex_07_g: see ex_07_g.txt.
# Source: graph_hdc revision/consolidated (bo_benchmark.py merged from revision/ex24-bo; runner run_ex24_kcist.sbatch).
#   The lines rebuild the final state (rerun of 2026-10-13, 29,200 campaigns, KCIST jobs 51249-51289, submitted by
#   submit_rerun.sh: tasks files per wave, encode -> run -> cleanup per wave) from scratch with the current code; no
#   command file of the runs exists in the repository (they were sbatch environment variables). Local copy of the
#   results: graph_hdc/.claude/worktrees/ex24bo/.../_ex24/kcist_rerun/ (campaigns.tsv, runs/).
# Runs: 29,200 campaigns = 9 objectives x 100 campaigns x (8 sizes x {hdf_matern, hdf_linear, morgan_tanimoto} + up to
#   8 sizes morgan_pca (FreeSolv/BEET fewer: PCA <= N-1 components) + random); 78 command lines: featurize 1, tasks 7,
#   per wave encode 2 (w0) / 5 (w1-w5) + run 6 shards + cleanup 1, collect 1.
# Protocol: objectives clogp (Crippen ClogP -> 15, AqSolDB), qed (-> 0.2, ZINC250k, whole library scored every round),
#   solubility (max, AqSolDB), lipophilicity (max), freesolv (min), beet (max log10 LD50, exact values), qm9_gap (min)
#   and qm9_dipole (max; both without zwitterions/ylides), melting_point (max, open melting point); stereo duplicates
#   merged. Methods hdf_matern (HDF standard configuration, depth 2, Matern-5/2 on centred/globally scaled inputs),
#   hdf_linear (HDF + linear/cosine kernel; the HDF surrogate of Fig. 5), morgan_tanimoto (radius 2, binary, folded to
#   D bits), morgan_pca (first D PCA components of Morgan-2048, Matern-5/2), random. Sizes 8-1024; 100 campaigns per
#   cell, campaign k shares its initial molecules across methods and has its own HDF codebook (seed 1000 + 100 k);
#   budget 20 initial + 150 single picks (FreeSolv 20 + 80, BEET 10 + 40); LogEI; GP fits via BoTorch 0.16.0 / GPyTorch 1.14.2.
# Analysis: python analyze_ex_24.py   (-> _ex24/analysis/summary.tsv|md, tests.tsv|md: paired Wilcoxon, Holm within each
#             objective; families hdf_vs_morgan, hdf_linear_vs_morgan, vs random)
#           python make_figure_bo.py figures   (-> figure_bo.pdf = Figure 5, figure_bo_si.pdf = Figure S3; reads
#             campaigns.tsv, runs/ and analysis/tests.tsv; default output folder _ex24/analysis)
#           python make_tables_bo.py _ex24/analysis   (bo_hdf_linear.tex, bo_runtime.tex: both tables were dropped from
#             the SI on 2026-10-14; optional)
# Cost: KCIST "small" nodes (64 CPUs, 4x RTX 4090, 400 GB requested): per wave about 45 min of encoding (5 nodes, ZINC250k
#   D=1024 is the critical path, ~40 min per encoding at 4 threads) plus about 17 min of campaigns (6 nodes, 24 workers
#   each; ZINC250k acquisition on the GPUs: 20-39 s per campaign up to D=128, 111-158 s at 1024); the whole rerun took
#   about 9 h, i.e. roughly 3,000 CPU-h plus ~100 GPU-h. On CPU only (gpus -> 0), the ZINC250k/QED campaigns dominate
#   (acquisition ~1.5 s per round on a CPU core vs ~0.1 s on a GPU).
# Notes: all data and results go to _ex24/ (or $EX24_ROOT). Disk: the HDF encodings take ~3.4 GB per campaign (all
#   libraries and sizes), hence the waves with cleanup (peak ~50 GB per 15-campaign wave; ~330 GB without cleanup).
#   Each encode worker holds the graphs of one library (~5 GB for ZINC250k). Every result file is written atomically and
#   finished campaigns/encodings are skipped, so any stage can be re-run to resume. The datasets (aqsoldb, zinc250k,
#   freesolv, lipophilicity, beet, qm9_smiles, open_melting_point) come from chem_mat_data; featurize loads them one
#   after the other. Left out on purpose: the stages morgan (added D=256 to libraries featurized before 2026-10-13)
#   and objectives (rewrote the objective files for 100 campaigns and the zwitterion mask), and calibrate; with the
#   current code, featurize writes the same files directly (verified on KCIST: re-featurizing reproduced the
#   libraries byte-identically, and objectives --verify-against checked the initial designs of campaigns 0-24).
#   Stripped from the runner: environment (OMP/MKL threads = --threads, TMPDIR on the node, PYTORCH_ALLOC_CONF=
#   expandable_segments:True, PYTHONWARNINGS=ignore). The 6 run shards of a wave are independent (any number of shards
#   works; --num-shards 6 is what ran).
